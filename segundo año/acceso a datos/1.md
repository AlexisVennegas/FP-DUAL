# ¿Cuál es cuál?

## Puerto 80

Es el puerto oficial por defecto para el protocolo HTTP (tráfico web no seguro).

## Puerto 8080

Es un puerto alternativo para HTTP, muy usado cuando el puerto 80 está ocupado o para aplicaciones locales.

Fuentes:

- [Kodu Cloud: puertos comunes de localhost](https://blog.kodu.cloud/es-ES/common-localhost-server-ports/)

## Puerto 443

El puerto 443, frecuentemente confundido con «4403», es el puerto oficial por defecto para HTTPS (tráfico web cifrado y seguro).

Si te refieres estrictamente al puerto 4403, no es un estándar oficial de la industria para HTTPS, sino un puerto personalizado que alguien pudo configurar manualmente para un servicio cifrado o específico.

Fuente:

- [Keyfactor: HTTP vs. HTTPS](https://www.keyfactor.com/es/blog/http-vs-https-whats-the-difference/)



## Secure Sockets Layer (SSL)

**Secure Sockets Layer (SSL)** es un protocolo diseñado para cifrar la comunicación entre un cliente y un servidor. Su objetivo era proteger datos como contraseñas, mensajes y datos bancarios frente a escuchas o modificaciones.

Actualmente, SSL está obsoleto y ya no se considera seguro. Fue sustituido por **TLS (Transport Layer Security)**, aunque muchas personas siguen usando «SSL» para referirse genéricamente al cifrado HTTPS.

### Relación con HTTPS y los puertos

- **HTTPS** utiliza TLS para proteger el protocolo HTTP.
- El puerto **443** es el puerto predeterminado de HTTPS.
- El puerto **80** corresponde normalmente a HTTP sin cifrado.
- Los certificados digitales permiten autenticar el sitio web y establecer una conexión cifrada.

En resumen, SSL fue el precursor de TLS; para sistemas actuales debe utilizarse TLS, no SSL.

## Stateless

Un sistema **stateless** (sin estado) no guarda información de la sesión del cliente entre peticiones. Cada solicitud debe incluir todos los datos necesarios para procesarla, por lo que cualquier servidor puede atenderla.

Esto facilita la escalabilidad y el uso de servidores distribuidos, aunque puede requerir enviar más información en cada petición. HTTP es, por naturaleza, un protocolo stateless; las sesiones, cookies o tokens permiten añadir estado cuando es necesario.



## URL, URI y URN

- **URI (Uniform Resource Identifier):** identificador genérico de un recurso. Puede indicar su ubicación o simplemente su nombre.
- **URL (Uniform Resource Locator):** tipo de URI que indica dónde está un recurso y cómo acceder a él, por ejemplo: `https://ejemplo.com/pagina`.
- **URN (Uniform Resource Name):** tipo de URI que identifica un recurso por un nombre persistente, sin indicar su ubicación, por ejemplo: `urn:isbn:9780131103627`.

En resumen, toda URL y toda URN son URI; una URL localiza un recurso, mientras que una URN lo identifica mediante un nombre.



## TCP y UDP

- **TCP (transfer Control Protocol):** protocolo orientado a conexión que garantiza la entrega ordenada y fiable de los datos. Se utiliza, por ejemplo, en HTTP/HTTPS, correo electrónico y transferencia de archivos.
- **UDP (User Datagram Protocol):** protocolo sin conexión, más rápido y ligero, pero sin garantizar la entrega ni el orden de los paquetes. Es habitual en streaming, videojuegos y llamadas en tiempo real.

En resumen, TCP prioriza la fiabilidad y UDP la velocidad y la baja latencia.

# Componentes de la web

- **Recursos:** documentos, vídeos, textos, aplicaciones y audios disponibles en Internet.
- **URI y URL:** identifican los recursos y, en el caso de las URL, indican cómo localizarlos.
- **Clientes web:** navegadores que solicitan y muestran los recursos mediante su URL.
- **Servidores web:** reciben las peticiones HTTP y entregan recursos, especialmente contenido estático como HTML.
- **Servidores de aplicaciones:** ejecutan la lógica de negocio y gestionan operaciones complejas y transacciones.
